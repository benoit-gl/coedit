# Packed immutable record prototype — in progress

Scratch experiment only: `/workspace/work/merge10-packed-prototype`. No tracked repository edits or remote actions. No production eligibility claim.

Intent: retain distinct logical record IDs, effect IDs, origin records and historical references while storing multiple immutable records in each physical unit. Compare against the same event history with one physical record per unit. Retain all history; do not claim this preserves separate per-edit transaction guarantees when batching writes.

Initial scope: bounded microprototype using the installed public Automerge carrier APIs and a stable logical-ID-to-packed-slot reader. Inspect existing Step 3 record contracts and conflict behavior before choosing exact encoding. Test immutable append, save/load, historical views, references and concurrent publication/conflicts. Heavy runs will be coordinated with the parent first.

Status: design inspection started; implementation and measurements pending.

## Implemented bounded design and first correctness checkpoint

Source snapshot in `merge10-packed-prototype/source/` is bound to repository revision `7618ee8939f305260a3d2a54b30a482093826fe4` by `source-binding.json` (64 files; installed Automerge 3.4.1 Node WASM hash included). Tracked repo is untouched.

`packed-store.mjs` uses one bootstrap native `units` map and public Automerge `Uint8Array` scalar values. Unit keys are SHA256 of canonical UTF-8 JSON arrays of existing canonical record tuples. UUID sorting gives deterministic slots. Each exact original canonical tuple, record UUID, Ref commitment, effect pair, batch, origin, source anchor and manifest reference is preserved. Refs continue to identify logical records, never a physical unit or slot. Logical-ID-to-unit/slot locations are a disposable cold-derived cache; no extra native locator records are claimed free.

One append call remains one native transaction. Primary candidate packs only records that already belong to that call (one semantic command), capped at 64 records/unit; it does not defer an edit to fill a future pack. A width-one scalar-unit control isolates packing from removal of the 32-level UUID trie; the original primitive is the third comparison. Multiple edits do not share mutable open packs. Separate per-edit native changes/heads are retained, but this is not a full carrier implementation or proof of native command authorization.

Cold load/merge inspects every scalar conflict alternative and supported public `getAllChanges`/`decodeChange` history. It rejects deletion, replacement with predecessors, malformed bytes/commitments, metadata/map replacement, conflicting logical UUID bodies and foreign lineage. Public Automerge elides assignment of exactly identical bytes as a no-op; that no-op is accepted. This validator concerns the supplied history, not cryptographic author authenticity or reconstruction detection. No history is dropped by this implementation.

Real fixture: `history16.json`, 16 alternating Unicode insert/delete edits after a seed, 18 command groups including genesis, 122 exact records. Original carrier snapshots and independent protocol reference validation agree at each capture. All 12 correctness cases currently pass (`correctness16.json`): width-one/packed exact refs and all retained native heads, old-root text/Origin projections after final reload, concurrent disjoint/identical scalar units with actual conflicts, equivocation atomicity, malformed conflicts, deletes/rewrites and metadata/layout/lineage failures. No existing full-carrier provenance tests were adapted or claimed to pass for a packed carrier.

Bounded measurements have started sequentially after parent granted the measurement slot: 4 and 16 edits, original trie / scalar-unit-per-record / one-command-pack, separate build and fresh-load workers, default heap limit, explicit GC. Results pending.

## Interpretation and remaining boundary

The prototype demonstrates that distinct logical records and command/effect/Origin/history semantics can remain explicit while multiple records share an immutable physical scalar. Its saved per-command changes refute a need to flatten edits or truncate history to obtain these bounded primitive savings.

It does **not** implement the complete native document carrier, native closed-command provenance, semantic-root/descriptor/ownership publication, retained carrier capture-token adapter, restoration/migration, or full existing native qualification tests. Native history validation rejects unsupported mutations in supplied history but is not authentication of authors or reconstructed history. Logical Refs stay separate from physical locations; lookup needs a derived cold-built cache. Cold load scans all units/history and flat native map width grows with history. A 64-record cap does not bound bytes per pack. Complete-carrier load overlap, flat-map scaling, adversarial carrier provenance and larger-history lifecycle behavior remain separate work. No production eligibility or overall application latency/memory conclusion is justified.

## Post-measurement independent-review fixes

Review found a real robustness defect outside measured inputs: historical `Packed.load(encoded, width)` did not check width, so width zero/negative could reach a non-advancing append loop. H500/H16 always supplied 1 or 64. Corrected candidate, runtime and focused tests are in the **new** `merge10-packed-prototype/post-review-fix/` directory. The original measured `packed-store.mjs`, every original H500 artifact and all 120 files bound by the historical artifact manifest were rehashed and remain byte-identical. No H500 performance/memory result is reassigned to the corrected code.

Fixed candidate validates width in shared constructor, create/load, and defensive append entry. Nine invalid width values now reject synchronously at all four boundaries. The malformed-conflict case now executes both cold-load rejection and merge rejection with exact accepted-state preservation; identical-byte native reassignment is accurately named as an accepted no-op. Copied source extraction now rejects unequal canonical bodies sharing a UUID, with an adversarial test. Final focused result: **14 cases pass**, plus syntax checks. Exact command and new hashes: `post-review-fix/README.md`, `post-review-fix/manifest.json`. This is post-measurement correctness work, not a new benchmark.

Source construction and full historical protocol-reference validation may fail at default heap; preserve explicit phase completeness rather than claim a full pass.
